# Local csTimer fork

- Keep this local csTimer fork and its approved UI as the reference. The user has now explicitly requested genuine Rust desktop and Kotlin Android implementations matching that interface; their sources are in `native/` (see `native/AGENTS.md` and `NATIVE.md`). Preserve the working web client and its data.
- This repository is a local fork with upstream history and an `upstream` remote. The existing browser client and Rust companion coexist with the new Rust main timer and Kotlin Android client. Do not claim physical Bluetooth/gyro validation or universal pixel-perfect parity from simulated tests or screenshots.
- Keep additions optional. The optional interface lives in `src/interface`, `local-interface.js` and its CSS; its clock mirrors the upstream active clock and its record actions call upstream statistics. First-run preferences never overwrite existing settings or sessions. Classic mode remains available through Options or `?interface=classic`.
- The user rejected the previous Snappy colors, all seven replacement palettes, and the Signal preview. The current revision changes the composition: session rail, centered cube/time, horizontal CFOP dock, and a dedicated review-tools rail. Options → Appearance offers Light (`paper`) and Dark (`carbon`); retired palette preferences migrate to Light without changing history. The user responded “much better” to this composition; preserve the centered timing layout while refining History. Use Geist Sans Regular/Medium/SemiBold for controls, labels and notes, paired with Maple Mono NF Regular/SemiBold for the clock, notation and measurements. Keep natural tracking, metadata at least 12px and normal controls/data at 14px. Preserve explicit timer size/decimal preferences and upstream handlers.
- Acubemy study findings and limits are summarized in `LOCAL.md`. Prefer a short path from case evidence to the corresponding drill; do not present population algorithm popularity as predicted personal improvement, or claim untested training/Bluetooth behavior was verified.
- Twisty Timer's original v4.7 source and official screenshots are also studied in `LOCAL.md`; Android runtime behavior remains untested. Borrow its focused timing states and contextual result/case actions. Preserve the user's compact history list instead of copying its card grid. Its manual case-progress slider and total-time trainer are not smart-cube mastery or recognition measurements.
- Preserve upstream GPL and all font licenses. Do not include private credentials, cube addresses, browser profiles, or real history in Git.
- Timing, move counting and reconstruction remain upstream-authoritative. Document upstream HTM semantics rather than silently substituting the older application's executed-turn counter. Never invent measured TPS for manual entries.
- Average TPS and mean moves use eligible samples from the same time-trimmed window as time averages, independent of the metric selected for the table. Display sample coverage.
- The GAN16 uses the existing GAN v4 transport. Do not claim gyro support: upstream ignores v4 gyro packets. Browser Bluetooth pairing and physical hardware testing require the real device; browser simulations are separate evidence.
- `local-scramble-guide.js` uses upstream cubies to keep the original scramble, insert exact inverse recovery moves at the cursor, signal partial half turns, and allow commuting opposite faces. It only formats guidance; csTimer decides readiness and timing. Unexplained packets and unsupported notation defer to the upstream hint.
- `companion/` is the Rust desktop widget, reading a same-origin local state bridge. It never opens a Bluetooth connection. A stale or closed timer must clear the connection indicator. X11/Xwayland provides always-on-top behavior. Do not share live cube data with public services.
- Build with `nix develop --command npm run build`, test with `npm test` and `nix develop --command make check`. Check real browser workflows, settings persistence and responsive screenshots.
- Serve on loopback. Build source templates without production analytics. Keep the previous cube-lab repository and its database unchanged unless a migration is explicitly requested.

- Full History search/filtering must remain presentation-only: preserve scorebook indices, upstream averages and penalties. Keep pagination lazy, and never reconstruct every solve just to search notes or formatted times. Row details call upstream stats; keep keyboard navigation from triggering the timer.

- The finalized History histogram uses two close ice-blue shades, contiguous bins, and a narrower desktop plot beside median/standard deviation/P90/DNF statistics. Preserve this approved direction; avoid introducing new chart hues during unrelated changes.

- The cube now uses the user-requested cartoon style: softly rounded caps, matte face colors, charcoal shoulders/seams and banded toon lighting. Preserve live facelet mapping and turn animation; do not restore photographic HDR reflections during unrelated UI changes.

- The right rail is dedicated to Cross/Algs/Technique tools. CFOP pause + execution is shown inline; do not restore the phase magnifier. Tags/favorites/groups use record[5].localReview through stats.setReviewTags, preserving comments and other metadata. The pace reference is the complete non-DNF session mean. Cross search runs in the upstream solver worker on the selected historical scramble; algorithm alternatives must be verified on that reconstructed case before display. Never infer actual finger positions or promise personal speed improvements from move count.

- Keep the cartoon renderer instanced and demand-driven (four draw calls, <60k triangles at the normal view). Do not add an idle RAF loop, forced supersampling, or restore `preserveDrawingBuffer`. Maintain bounded verified turn queues, hidden/reduced-motion state coherence and graphics-context recovery. Keep `.local-build` free of obsolete HDR/fonts/shaders while preserving their licensed sources. Run `npm run test:browser:performance` for renderer or frame-scheduling changes.
